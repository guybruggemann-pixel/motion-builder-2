# src/app rules

- The doc lives in `store/docStore.ts` only. Change it with `docStore.getState().edit(label, recipe, { coalesce })`; never mutate it or keep a copy in component state. Edits that fail `validateDoc` are rejected.
- Drags and typing: pass the same `coalesce` key on every intermediate edit and call `commit()` on release, so one gesture is one undo step.
- `store/uiStore.ts` is view state (playhead, open subnet path, toggles). Nothing in it may change what gets rendered or exported.
- Pixels come from `evaluateFrame` through a `FrameCache`. Render code (`render/`) maps drawables to canvas calls and holds no scene logic; it must stay free of React because the phase 2 web render reuses it.
- Measure text with `canvasMeasure()` only after `loadFonts()` resolves; a cache built on fallback metrics lays text out wrong.
- Styling: tokens and components from `design-system/` (soft direction, `docs/ui-handover.md` §1): tokens only, no raw colours in UI. `ink` (black pill) = where you are or the main action, `raised` + shadow = selected, `volt` only for live state and always with ink on it or around it. Old names (`primary`, `muted`, `border`…) still map onto the new tokens; prefer the new ones (`card`, `field`, `ink`, `line`, `line2`, `volt`). Canvas code reads tokens with `getComputedStyle`, so `setTheme` flips the `.dark` class before the store notifies.
- Layout: `.shell` grid in `styles.css` (rail, library, viewer, inspector, timeline; stacks under 900px). Cards are `rounded-xl bg-card shadow-card`. Library width, inspector width and timeline height are `uiStore.panes` (view state, saved per browser on release), set as CSS variables on `.shell` and dragged with `shell/Splitter.tsx` handles in the grid gaps (arrow keys step, double-click resets).
- Ease names in the UI come from `MENU_EASES` (Motion Builder v1 vocabulary).
- Timeline edits live in `timeline/edits.ts` as plain immer recipes (tested in `test/timelineEdits.test.ts`); components only translate pointer gestures into them. Times are snapped to whole frames before they reach a recipe.
- Moving a layer bar shifts its own keys (AE), Subnets included (instance keys are in parent time); trimming doesn't. Subnet contents run on local time, so they follow on their own.
- Drags listen on `window`, never on the pressed element: edits re-render the timeline mid-gesture and the element can be replaced.
- The open-network path is a list of crumbs `{ network, node }` in `uiStore`; use `store/navigation.ts` to open or leave a subnet so the playhead stays on the same moment.
- Inspector edits live in `inspector/edits.ts` (tested in `test/inspectorEdits.test.ts`). Value semantics follow AE: on a keyed param, a change at the playhead sets or adds the key there; otherwise it sets the base value. "At the playhead" means within half a frame.
- Inspector controls call `onChange(value, final)`; intermediate values coalesce into one undo step and the final one commits it. Keep that contract for any new control.
- A Subnet's promoted controls are edited as params on the instance; reset deletes the param so the asset's own value shows again.
- Network view: xyflow's controlled pattern. A local node list takes xyflow's own changes (`applyNodeChanges`: measured sizes, drag positions) and is re-synced from the doc on every edit, keeping the measured sizes; never rebuild nodes from the doc without them (wires vanish until re-measured). Graph edits live in `network/edits.ts`.
- Testing in a background browser tab: ResizeObserver doesn't run until the tab paints, so xyflow nodes read as hidden there. Take a screenshot of the tab first.
- Graph editor (`timeline/GraphEditor.tsx`): a segment's shape is its starting key's ease string; handles write `cubicBezier(x1,y1,x2,y2)` through `setKeyEase`. Menu eases convert via `BEZIER_OF` (standard approximations, tested within 0.08).
- `render/prores/anime-ae-prores.es3.js` is v1's ProRes 4444 encoder, verbatim. Don't edit it; it's loaded as text (`?raw`) and evaluated so the page, workers and tests run the same code. `test/prores.test.ts` checks its output with ffprobe/ffmpeg when they are installed.
- Batch (`batch/BatchPanel.tsx`): settings are `doc.batches[0]` (undoable edits); rows are view data fetched from the sheet and never stored in the doc. A row's output key is a hash of the row-applied doc, so any template change re-renders every row.
- AE export (`export/`): `anime-ae-bake.es3.js` is v1's baker, verbatim. `aePlan.ts` samples `evaluateFrame(…, { flattenSubnets: false, instance })` and bakes channels; `ae-build.jsx` (ES3) builds AE from the plan. `test/aeExport.test.ts` runs the .jsx against a recording mock of AE; keep the mock in step when the script uses new AE calls.
- Selection is the spine: `uiStore.selectedNodes` drives the viewer outline and contextual toolbar (`viewer/Selection.tsx`), the timeline tree, the inspector and the network. The viewer hit-tests evaluated drawables (`render/bounds.ts`); flattened subnet contents select their instance (`ownerIn`). The bottom card's tab is `uiStore.bottomTab` so other places can open the Graph.
- Materials until phase D: a material is a Solid colour, applied by setting the layer's `fill` (`panels/materials.ts`, one undo step); tiles drag with the `SOLID_MIME` type onto timeline rows or the viewer.
- "Designers can edit" (`setDesignerEditable` in `inspector/edits.ts`) promotes a layer's text (Text) or fill (Shape) on its asset network as `<node>-<param>`; off removes every control that targets the layer.
- Glyph outlines for 3D text (`render/outlines.ts`): the bundled WOFF2 files are unpacked to TTF (wawoff2's wasm binding, loaded as `?raw` text and run with our own `Module`, because its wrapper only exports under Node; copy its output, it's a view into wasm memory), then fontkit varies the weight and shapes. Don't use fontkit's `getVariation` on WOFF2 directly: it breaks on variable glyf tables. Outlines are in the core's layout space and match `canvasMeasure` widths exactly (checked in the browser).
- 3D pass (`render/three/`): `install3D()` (called in `main.tsx`) plugs `ScenePass` into `canvas2d` via `setScene3DRenderer`. three.js and the outline fonts load on first use (one placeholder frame, then `requestRedraw`); before a final render, `await load3D()`. The pass renders at the layer's on-screen device size (from the context transform, capped at 4096) and is drawn with `drawImage` from [0, 0] to the layer size. Studio environments are built in the constructor: generating one mid-render empties that frame. Geometry is cached by its inputs (300 entries). `stats3D` counts placeholder and rendered frames for debugging. three is pinned (0.186.1).
- Debugging in the browser pane: modules imported by hand (`import('/render/…')`) can be a different instance from the app's (Vite adds `?t=` to edited files), so read state through the DOM, not module exports. A background tab doesn't size the viewer until it paints: take a screenshot first.
- Final renders (`renderJob.renderToBlob`) await `load3D()` when the doc has a Scene3D, so a file never contains the placeholder. `renderComp` only draws a background for a network that is itself a comp: a subnet or 3D network rendered on its own keeps alpha (that's what AE passes need).
- AE export with 3D: `buildAePlan` returns `passes`; each 3D layer is a `footage` layer whose ProRes pass the Render panel renders into the folder the user picks, next to the .jsx. The script imports passes from its own folder (`new File($.fileName).parent`) and alerts with the missing file names. Keep the mock in `test/aeExport.test.ts` in step (File, ImportOptions, importFile, addNull).
- Never use `window.confirm` / `alert` / `prompt`: the app's embedded browser pane dismisses them silently. Confirm inline (see Library › Presets), and only when there's something to lose.
- "+ Add" (`panels/AddMenu.tsx`) wires new layers and 3D objects into what the network draws (`wireToOutput`: into the output's Merge, or a new Merge in front of a single-input Output), so they show at once; a Material goes into the selected object's free material input. It lists 3D objects only inside a 3D scene. Menus that leave a card use `position: fixed` (cards clip with `overflow-hidden`).
- 3D in the viewer: clicks pick the 3D object under the pointer (`pick3D`, a raycast in the pass); empty 3D space falls through to what's below. Dragging a selected 3D object, or a selected 3D scene layer (its first object), turns it (`viewer/turn3d.ts`: left/right = Y, up/down = X, 0.4°/px, Shift = one axis) through `setValue`, one undo step per drag. A selected object inside a 3D scene is outlined with its projected box (`box3D`). The pass lives in one shared object on `globalThis` so every module copy uses it.
- A Scene3D layer's own transform is a flat 2D placement in the comp ("Placement in the comp (2D)"); its objects carry the 3D transform. The inspector lists a scene's objects ("In this scene") and Look shows a wired Material instead of the fill.
