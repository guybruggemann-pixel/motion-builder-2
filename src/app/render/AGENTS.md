# src/app/render rules

- `render/prores/anime-ae-prores.es3.js` is v1's ProRes 4444 encoder, verbatim. Don't edit it; it's loaded as text (`?raw`) and evaluated so the page, workers and tests run the same code. `test/prores.test.ts` checks its output with ffprobe/ffmpeg when they are installed.
- Glyph outlines for 3D text (`render/outlines.ts`): the bundled WOFF2 files are unpacked to TTF (wawoff2's wasm binding, loaded as `?raw` text and run with our own `Module`, because its wrapper only exports under Node; copy its output, it's a view into wasm memory), then fontkit varies the weight and shapes. Don't use fontkit's `getVariation` on WOFF2 directly: it breaks on variable glyf tables. Outlines are in the core's layout space and match `canvasMeasure` widths exactly (checked in the browser).
- 3D pass (`render/three/`): `install3D()` (called in `main.tsx`) plugs `ScenePass` into `canvas2d` via `setScene3DRenderer`. three.js and the outline fonts load on first use (one placeholder frame, then `requestRedraw`); before a final render, `await load3D()`. The pass renders at the layer's on-screen device size (from the context transform, capped at 4096) and is drawn with `drawImage` from [0, 0] to the layer size. Studio environments are built in the constructor: generating one mid-render empties that frame. Geometry is cached by its inputs (300 entries). `stats3D` counts placeholder and rendered frames for debugging. three is pinned (0.186.1).
- Final renders (`renderJob.renderToBlob`) await `load3D()` when the doc has a Scene3D, so a file never contains the placeholder. `renderComp` only draws a background for a network that is itself a comp: a subnet or 3D network rendered on its own keeps alpha (that's what AE passes need).
- AE passes (`render/passes/`): `plan.ts` decides elements (top-level layers in paint order, then 3D objects of scene layers) and files; `export.ts` renders everything in one frame-stepped sweep: each layer alone (`renderComp` `only` + `transparent`), 3D scenes in ID colours (`scene3d: { kind: "id" }`, three objects per render) and depth (`{ kind: "depth", near, far }`, range over the shot), derives mattes and puzzles with `coverage.ts` (visible coverage = alpha × what's above leaves), and encodes all outputs through one ProRes worker pool. Then `passesScript` writes the assembly .jsx. Keep every pass from the same evaluated frame so they line up with the beauty.
- Encoder back-pressure: use `pool.submit` / `pool.drain`. Never `Promise.race` over promises that may have settled: it spins without yielding and froze (crashed) long renders.
- Clones render as one `InstancedMesh` per object (`instanced` in `render/three/pass.ts`); clone colours become instance colours over a white material. The depth shader honours `USE_INSTANCING`; pick, outline box and depth range go over every clone. "+ Add" inside a 3D scene chains a Cloner after a selected object and an effector after a selected Cloner or effector (`insertAfter`), and plugs a field into the selected effector.
- Reflective looks (`render/three/pass.ts`): metals (metalness > 0.5) and glass use a separate softbox "reflect" environment as their own envMap at full strength; the dim room environment stays the fill for everything else. Glass has no backdrop to refract in this pass, so it is a dark, partly transparent body with strong reflections (premultiplied), not transmission.
- AE passes: beauty + optional mattes, puzzle, depth, normals (camera-space, unlit, linear). New AOV kinds land in the Mattes precomp automatically via ae-passes.jsx.
- Ambient occlusion: `ScenePass.renderAO` (GTAO via EffectComposer, cached, radius ∝ scene size) runs only for beauty when `ambientOcclusion > 0.01`; data passes stay plain renders.
- Renders must be the same in every session: nothing in the pass may use `Math.random`. three's GTAOPass seeds its denoise texture randomly, so `renderAO` swaps in `seededNoise()`; check any new three add-on for the same thing (`bun run render:check` catches it).
- Headless renders (`src/app/headless/`, driven by `tools/render/`): `window.mbHeadless.render` on the `/render` route runs `renderToBlob` / `renderComp` after loading fonts, images (`preloadImages`) and the 3D pass. Anything new that loads lazily in the viewer must be awaited there too, or frame 0 renders without it.
